## The 5-Layer Enforcement Framework

Every solution MUST have AT LEAST 3 of these layers:

### Layer 1: Bootstrap Integration
**Question**: Is it in bootstrap-utils or referenced there?
- Makes it visible to fresh sessions
- Automatic discovery
- No memory required

### Layer 2: Trigger Mechanisms
**Question**: What actions/phrases trigger this solution?
- Specific phrases that force usage
- Situations that require it
- Automatic activation

### Layer 3: Red Flag Systems
**Question**: What prevents bypassing this?
- Warning signs if skipped
- Blocks on incorrect usage
- Automatic enforcement

### Layer 4: Memory/Discovery Paths
**Question**: How many ways can this be found?
- Memory edits (if space available)
- Cross-references in docs
- Multiple file locations
- Conversation search

### Layer 5: Self-Verification
**Question**: How does the solution verify itself?
- Checkpoints that confirm usage
- Success metrics
- Failure detection

## Failure Modes & Prevention

### Failure Mode 1: "We'll just remember"
**Prevention**: Banned response. Must define mechanism.

### Failure Mode 2: "It's documented"
**Prevention**: Documentation alone is insufficient. Need 3+ layers.

### Failure Mode 3: "It's in memory"
**Prevention**: Memory is full. Must have bootstrap integration.

### Failure Mode 4: "We can search for it"
**Prevention**: Must have automatic triggers, not just search.

### Failure Mode 5: "Next session will figure it out"
**Prevention**: Must define explicit discovery mechanism NOW.
